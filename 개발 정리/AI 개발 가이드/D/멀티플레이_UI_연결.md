# 게임 UI 멀티플레이 연결

2026-11-02. 기존 메모리 기반 자동 4인 데모 대신 실제 TCP 접속을 사용한다.

## 실행

1. 모든 PC에서 같은 버전의 프로젝트로 `Assets/Scenes/DevTabletUI.unity`를 열고 Play한다. 이 씬을 기본 빌드 씬으로도 등록했다.
2. 방장은 이름과 포트(기본 `7777`)를 입력하고 **방 만들기**를 누른다. 방장 주소 입력 칸은 참가할 때만 사용한다.
3. 다른 PC는 대기실에 표시된 방장 PC의 IPv4 주소와 같은 포트를 입력하고 **참가**를 누른다. `127.0.0.1`은 같은 PC에서 테스트할 때만 쓴다. 주소가 여러 개면 참가자에게 도달 가능한 실제 연결의 주소를 사용한다.
4. 방장은 사람이 모두 입장한 뒤 **빈자리를 BOT으로 채우기**를 선택할 수 있다. 자동으로 4인까지 채우며 처음부터 BOT을 넣지는 않는다. **BOT 모두 내보내기**를 누르면 사람이 참가할 자리를 다시 확보한다.
5. 사람들은 **준비**를 누른다. BOT은 자동 준비한다. 4명이 모두 준비하면 방장이 **게임 시작**을 누른다.
6. 기존 정보 구매·기업 선택·투자 주문·시장 공개·정산 화면으로 이어진다. **방 나가기**로 접속 화면에 돌아갈 수 있다. 방장이 나가면 방은 종료되고 참가자 화면에는 종료 이유와 이미 받은 결과가 남는다.

## 동작과 현재 범위

- 서버는 모든 로컬 IPv4 인터페이스에서 수신한다. 화면 연결은 PC 방화벽이나 학교 Wi-Fi의 단말 간 통신 제한을 바꾸지 않는다. 기존에 허용한 참가자 외의 PC에는 별도 방화벽 허용이 필요할 수 있다. 빌드 실행 파일의 방화벽 규칙은 Unity Editor와 별개다.
- 방장만 원본 시장을 로드하고 실제 `MarketService`와 `SharedInformationService`를 생성한다. 참가 UI에는 개인에게 허용된 정보만 전송한다. 에디터는 기존 서버 fixture, 빌드는 기존 예제 시장 생성 경로를 사용한다. 서버 fixture를 Resources/StreamingAssets로 옮기지 않았다.
- BOT은 기존 `DevBot` 전략이다. 정보를 구매하지 않고, 가능한 기업을 선택해 60:40·10→15일/5→10일 주문을 제출한다. 결과는 사람과 동일하게 실제 B가 계산한다. 무작위 투자 AI를 새로 추가한 것은 아니다.
- BOT 등록·제거는 대기실에 한정한다. 게임 도중 사람을 BOT으로 교체하지 않는다. 연결이 끊긴 대기실 참가자의 자리는 방장이 채우기를 눌렀을 때 예약을 해제한다.
- 접속 실패·포트 중복·정원 초과는 접속 화면에서 안내한다. 연결 대기는 제한 시간이 있고 취소할 수 있다. 접속 화면에서 다시 참가하는 것은 새 입장이다. 기존 API의 토큰 재접속은 유지되지만 이 UI의 자동 재접속 기능은 아직 없다.
- 게임 진행은 기존 구현 범위인 한 턴이다. 과거 정보·정산 내역을 보관하는 상태 저장소 정책은 그대로 사용한다.

## 검증

- `Tests/AValidation`: 기존 네트워크·A/B/C 연결 회귀 검사.
- Unity EditMode: 기존 규칙/상태/흐름 검사와 `NetworkGameUiTests`. 새 UI 테스트는 Play 모드에 들어가 방 생성, BOT 3인 추가/제거, 사람의 자리 재사용, 사람 2명+BOT 2명, 5번째 참가 거절, 개인 구매 정보 격리, 실제 B 정산 동기화, 방장 종료, 동일 포트 재생성, 잘못된 포트 및 연결 대기 취소를 확인한다.
- 자동 테스트는 한 PC의 여러 실제 TCP 클라이언트를 사용한다. 다른 물리 PC 및 학교 Wi-Fi 환경은 별도 현장 확인 대상이다.
